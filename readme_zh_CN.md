# Chronos

> 一个用 Go 语言编写的 AI 驱动个人日程调度工具。

Chronos 是我为自己打造的个人日程规划工具。

它接收我的可用时间、待办任务、现有日程安排以及其他约束条件，再通过 AI 模型生成一份每日计划。

我最开始是在学习 Go 语言时把它作为一个小型项目启动的，从那之后它已经迭代了不少版本，实现过程中有相当一部分内容是借助 AI（反重力） 辅助完成的。目前我仍在学习语法，逐步尝试独立理解、优化和重构代码。

所以这**并不是一个完成度很高、可直接投入生产环境的应用**。它本质上是一个个人项目，也是一次学习实验。

## 它能做什么？

* 🗓️ 借助 AI 生成每日日程安排
* 🤖 支持多款 AI 服务商/模型
* 📚 管理基础固定日程与灵活弹性任务
* 🔄 在遇到突发事件时自动重新规划日程
* 💾 在本地持久化存储日程与任务数据
* ⚡ 缓存已生成的数据，避免不必要的 API 调用
* 📧 通过邮件发送生成好的日程
* 🧩 自动维护每日 Codeforces 刷题练习计划
* 🌐 抓取并自动翻译 Codeforces 题目
* 🎭 自定义 AI 的调度风格与角色设定

整体工作逻辑如下：

```text
             ┌─────────────────┐
             │    基础固定日程   │
             └────────┬────────┘
                      │
             ┌────────▼────────┐
             │   弹性待办任务    │
             └────────┬────────┘
                      │
             ┌────────▼────────┐
             │   Codeforces    │
             │     刷题任务     │
             └────────┬────────┘
                      │
                      ▼
                ┌───────────┐
                │    AI     │
                │  智能调度器  │
                └─────┬─────┘
                      │
                      ▼
             ┌─────────────────┐
             │     每日计划      │
             └─────────────────┘
                      │
               遇到突发事件？
                      │
                      ▼
             ┌─────────────────┐
             │    重新规划      │
             └─────────────────┘
```

## 我为什么要开发这个项目？

我想要一款能适配我日常时间并非完全可预知这一特点的日程工具。

传统日历擅长回答这类问题：

> "下午2点安排了什么？"

但我想要的工具更接近于解答这类需求：

> "我有这些待办事项、这么多空闲时间、全天不同时段精力状态不同，现在又突然发生了意外状况，我现在该先做什么？"

这正是引入 AI 模块的意义所在。

Chronos 将 AI 定位成**规划执行者**，而非数据的唯一可信来源。

实际的日程、任务和缓存结果都存储在本地，AI 仅基于这些本地信息做出调度决策。

## 项目结构

当前项目大致按照功能职责划分目录：

```text
cmd/
└── chronos/          # 应用程序入口

internal/
├── ai/               # AI 客户端与模型交互逻辑
├── codeforces/       # Codeforces 题目抓取、进度追踪与翻译功能
├── config/           # 配置文件处理
├── email/            # 邮件发送相关功能
├── scheduler/        # 核心调度逻辑
└── storage/          # 本地数据持久化存储
```

这个目录结构目前仍在迭代优化中。

部分模块的代码比较规整，但也肯定存在不少可以优化的设计点。

## 技术栈

* **Go 语言**
* 本地数据存储使用 JSON / YAML 格式
* AI 服务 API
* Codeforces 平台接口
* SMTP 邮件发送协议

目前这个项目大量使用 Go 标准库，仅引入了极少数第三方依赖。

## 运行方式

### 环境要求

* Go 1.26 及以上版本
* 已接入的 AI 服务商对应的有效 API 密钥
* 可选：启用邮件功能所需的 SMTP 凭证

### 编译构建

```bash
git clone https://github.com/Hindenburg-dev/chronos.git
cd chronos

go build ./cmd/chronos
```

编译完成后直接运行生成的可执行文件即可。

> 配置相关的说明文档目前还在整理优化中，这部分内容后续也会随着项目迭代更新。

## 配置说明

Chronos 通过本地配置文件管理以下内容：

* AI 服务商选择
* API 密钥
* 调用的模型名称
* 邮件相关设置
* 调度器偏好参数

**请勿将 API 密钥或其他隐私凭证提交到公开代码仓库中。**

## Codeforces 集成功能

Chronos 可以自动维护每日 Codeforces 刷题练习计划。

当前的工作流大致如下：

```text
题库池
     ↓
进度追踪器
     ↓
分配今日刷题任务
     ↓
翻译题目与补充元信息
     ↓
纳入每日日程安排
```

翻译完成的题目信息也会在本地缓存，同一道题目不需要重复调用翻译接口。

## 关于 AI 辅助开发的说明

Chronos 项目有相当一部分代码是借助 AI 编程助手完成编写的。

我本身是在开发这个项目的过程中同步学习 Go 语言，所以有时候 AI 生成的代码我当下并没有完全理解透彻。

这也是我把这个项目开源到 GitHub 上的原因之一。

我希望逐步从：
```text
AI 编写代码 → 我调试到能运行
```
的状态，过渡到：
```text
我先理清设计思路 → AI 辅助实现细节 → 我审核最终产出
```

如果你在浏览代码的时候发现了任何逻辑冗余、设计不合理或者明显的错误，**完全欢迎你直接告诉我**。

我开源这个项目的核心目的就是为了学习进步。
